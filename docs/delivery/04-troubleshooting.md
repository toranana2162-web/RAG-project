# 想定トラブルと対処方法

システムの挙動・実装に基づくトラブルシューティング集。エラーメッセージは実装の表示文言に準拠。

---

## A. ログイン関連

### A-1. ログインメールが届かない
- **原因**: 許可ドメイン外のメール／メール送信のレート制限／迷惑メール振り分け。
- **対処**:
  - 入力メールが `ALLOWED_EMAIL_DOMAINS` に含まれるドメインか確認。
  - 迷惑メールフォルダを確認。
  - 短時間に何度も送るとレート制限に当たるため数分待つ。
  - 大量配信・独自ドメイン運用時は Supabase の SMTP（カスタム送信）設定を検討。

### A-2. リンクを押しても「ログインに失敗しました」/ ログインできない
- **原因**: リンクの期限切れ／使用済み／メールテンプレート設定不整合／別端末で開いた。
- **対処**:
  - **新しいメールを再送**し、最新リンクを使う（古いリンクは無効）。
  - リンクを**送信した端末と同じ端末・ブラウザ**で開く。
  - Supabase → Authentication → URL Configuration の **Site URL** と **Redirect URLs** に本番URL（`https://rag-prpject.vercel.app` と `/auth/confirm`）が登録されているか確認。
  - Magic link テンプレートが `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email&next=/chat` になっているか確認。

### A-3. 「このアカウントは利用できません（許可ドメインのみ）」
- **原因**: 許可ドメイン外のメールでログインを試みた（仕様どおりの拒否）。
- **対処**: 許可ドメインのアドレスでログイン。対象を増やす場合は `ALLOWED_EMAIL_DOMAINS` を更新し再デプロイ。

### A-4. 管理者なのに「文書管理」が出ない / `/admin` に入れない
- **原因**: `app_metadata.role='admin'` 未設定、または付与後に再ログインしていない。
- **対処**: 運用手順書 5章のSQLで付与し、**一度ログアウト→再ログイン**（権限はJWTに埋め込まれるため）。

## B. 質問・回答関連

### B-1. 正しい情報があるはずなのに「該当する情報を確認できませんでした」
- **原因**: 対象文書が未処理／類似度がしきい値未満／言い回しが離れている。
- **対処**:
  - 管理画面で対象文書が**「完了」**か確認（未処理・失敗なら処理/再処理）。
  - 質問に具体語（制度名・手続き名）を入れて言い換える。
  - 恒常的に取りこぼす場合は `RAG_SIMILARITY_THRESHOLD` を下げる／`RAG_RETRIEVAL_TOP_K` を上げる（下げ過ぎるとノイズ増）。`npx tsx scripts/eval/probe.ts <ID>` で検索状況を確認。

### B-2. 「検索に失敗しました。」
- **原因**: OpenAI(Embedding) または DB(検索) への一時的な通信断。
- **対処**: 少し待って再送（主要通信はリトライ実装済み）。頻発する場合は OpenAI APIキーの有効性・利用上限、Supabase稼働状況を確認。

### B-3. 「認証が必要です。」がチャットで出る
- **原因**: セッション切れ／認証確認の一時的な通信断。
- **対処**: 再読み込み。`/login` に飛ばされたら再ログイン。頻発時はネットワーク・Supabase稼働を確認。

### B-4. 回答は出るが出典のページ番号がずれている
- **原因**: 情報がページ境界にまたがる／評価データ側の期待ページ表記の差。
- **対処**: 出典はDB（抽出時のページ）に基づき表示。実PDFの該当ページを確認。体系的にずれる場合はチャンク設定を調整。

### B-5. 回答が返るまで遅い / タイムアウトする
- **原因**: 生成は非ストリーミングのため待ち時間が発生。ホスティングプランの実行時間上限。
- **対処**: 通常は数秒〜十数秒。頻繁にタイムアウトする場合は Vercel Pro を検討（`/api/chat` は `maxDuration=60`）。

## C. 文書取り込み関連

### C-1. アップロードが弾かれる（「PDF形式ではありません」等）
- **原因**: PDF以外／拡張子偽装／中身がPDFでない（先頭 `%PDF-` 不一致）／20MB超。
- **対処**: 正しいPDFを20MB以内で。分割やページ削減で軽量化。

### C-2. 「同じ内容のファイルが既に登録されています。」
- **原因**: SHA-256が一致する重複ファイル。
- **対処**: 重複登録は不要。改訂版なら**旧を削除→新を登録**。

### C-3. 処理が「失敗（failed）」になる
- **原因の切り分け**（行のエラー内容を確認）:
  - 「テキストを抽出できませんでした（スキャンPDFの可能性）」→ 画像PDFは非対応。OCR済みPDFに差し替え。
  - 「Embedding生成に失敗しました」→ OpenAI通信/キー/上限。キーと利用状況を確認し再処理。
  - 「チャンクの保存に失敗しました」等 → DB通信。時間をおいて再処理。
- **対処**: 原因解消後に「再処理」（冪等なので重複は生じない）。

### C-4. 大量PDFの処理が途中で止まる/遅い
- **原因**: 1文書ずつ同期処理のため件数・サイズに比例して時間増。実行時間上限。
- **対処**: 少数ずつ処理。大規模一括はローカル実行やジョブ基盤導入を検討（Phase2提案参照）。

## D. デプロイ・運用関連

### D-1. 変更が本番に反映されない
- **原因**: push先ブランチ違い／ビルド失敗／環境変数未反映。
- **対処**: `main` に push されているか、Vercel の Deployments でビルド成否を確認。環境変数変更時は再デプロイ。

### D-2. 本番でのみ設定系エラーが出る
- **原因**: Vercel の環境変数未設定／`NEXT_PUBLIC_SITE_URL` がローカルのまま。
- **対処**: 本番の環境変数7項目を確認。`NEXT_PUBLIC_SITE_URL` は本番URLに設定し再デプロイ。

### D-3. npm audit で脆弱性が出る（保守時）
- **対処**: 影響範囲を確認し、パッチ更新や `overrides` で対応（本番リリース時点では0件）。破壊的変更は検証環境で確認後に適用。

## E. エスカレーション時に集める情報

- 発生日時・利用者（一般/管理者）・操作手順・画面のエラーメッセージ。
- 対象文書名／質問文（機微情報は伏せる）。
- Vercel の Deployments / Function Logs、Supabase のログ。
- 外部API（OpenAI/Anthropic）の稼働状況・利用上限。
