# 運用手順書（クライアント向け）

本書は社内文書検索AI（RAG）の日常運用手順をまとめたものです。
対象システム: https://rag-prpject.vercel.app

---

## 1. 利用者区分

| 区分 | できること |
|---|---|
| 一般社員 | ログイン、質問、回答と出典の確認 |
| 管理者 | 上記に加え、PDF登録・処理・一覧確認・再処理・削除 |

管理者権限は後述の手順で個別に付与します。

---

## 2. ログイン（全利用者）

1. ブラウザで `https://rag-prpject.vercel.app/login` を開く。
2. **社内メールアドレス**を入力し「ログインリンクを送信」。
3. 届いたメールの「ログイン」リンクをクリック。
4. チャット画面（`/chat`）に遷移すればログイン完了。

補足:
- 許可された社内メールドメインのみログインできます（それ以外はエラー表示）。
- リンクは短時間で失効します。期限切れ時は再度送信してください。
- リンクは**開いた端末**でログインします（PCで送ったら同じPCで開く）。

---

## 3. 質問する（全利用者）

1. `/chat` で質問を入力（Enterで送信、Shift+Enterで改行）。
2. 回答と、その下に**出典（ファイル名／ページ番号）**が表示されます。
3. 文書に該当がない場合は「登録されている文書内に、該当する情報を確認できませんでした。」と表示されます（正常動作）。

コツ:
- 具体的な語（制度名・手続き名など）を含めると精度が上がります。
- 会話履歴は保存されません（1問1答）。前の回答を前提にした追い質問はできないため、1問で完結する形で質問してください。

---

## 4. 文書の登録（管理者）

1. `/admin/documents` を開く（管理者のみ表示）。
2. 「PDFを登録」からPDFを選択して「アップロード」。
   - 形式: PDFのみ / サイズ: 20MBまで / 同一内容の重複は登録不可。
3. 一覧に**「未処理」**で表示される。
4. 対象行の**「処理」**を押す。
   - 「処理中」→ 完了すると「完了 ・ Nページ ・ Mチャンク」に変わる。
   - これで検索対象になります（**処理しないと検索されません**）。

### 状態の意味
| 状態 | 意味 |
|---|---|
| 未処理 (uploaded) | 保存済み。まだ検索対象ではない。 |
| 処理中 (processing) | 抽出・ベクトル化を実行中。 |
| 完了 (completed) | 検索対象。ページ数・チャンク数が表示される。 |
| 失敗 (failed) | 処理に失敗。行にエラー内容が表示される。 |

### 再処理・削除
- **再処理**: 完了/失敗の行の「再処理」で再実行（冪等：重複チャンクは作られません）。
- **削除**: 「削除」で確認後、DBと保存ファイルの両方を削除（関連チャンクも自動削除）。

### 一括登録のコツ（初回など多数のPDF）
- 1件ずつ「アップロード→処理」を繰り返す運用です。
- 大きいPDFは処理に時間がかかります。件数が多い場合は分けて実施してください。

## 5. 管理者権限の付与（システム管理者向け）

Supabase ダッシュボード → SQL Editor で、対象ユーザーのメールを指定して実行:

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role":"admin"}'::jsonb
where email = 'admin@あなたの会社ドメイン';
```

- 反映には対象ユーザーの**再ログイン**が必要です。
- 権限を外す場合は `'{"role":"member"}'` などに更新（または role を削除）。

---

## 6. 許可ドメインの変更

Vercel のプロジェクト → Settings → Environment Variables で
`ALLOWED_EMAIL_DOMAINS`（カンマ区切り）を変更し、**再デプロイ**すると反映されます。

例: `example.co.jp,example.com`

---

## 7. 更新・デプロイ運用（開発担当向け）

- `main` ブランチに `git push` すると Vercel が**自動で本番デプロイ**します。
- 手動デプロイも可能: プロジェクト直下で `npx vercel --prod`。
- 環境変数を変更した場合は再デプロイが必要です。

### 環境変数一覧（本番はVercelに設定）
| 変数 | 用途 | 公開区分 |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | 認証メールのリンク先（本番URL） | 公開 |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase URL | 公開 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase Publishable key | 公開 |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase Secret key | **非公開** |
| `EMBEDDING_API_KEY` | OpenAI APIキー | **非公開** |
| `ANTHROPIC_API_KEY` | Anthropic APIキー | **非公開** |
| `ALLOWED_EMAIL_DOMAINS` | 許可メールドメイン | 非公開扱い |

## 8. 精度の再評価（任意）

実文書に基づく評価データ `scripts/eval/dataset.json` を用意し、開発環境で:

```bash
npm run eval scripts/eval/dataset.json
```

正答率・出典表示率・回答不能誤回答率が出力されます（合否判定つき）。
検索の当たり具合を個別に確認する診断は `npx tsx scripts/eval/probe.ts <質問ID>`。

---

## 9. 日常運用チェックリスト

- [ ] 新しい社内文書が出たら管理者がPDF登録→処理。
- [ ] 「失敗」の文書があればエラー内容を確認し、再処理 or 差し替え。
- [ ] 退職者等のアクセスは Supabase Auth 側で管理（無効化）。
- [ ] APIキーの利用量・課金（OpenAI/Anthropic）を定期確認。
- [ ] 文書改訂時は「旧を削除→新を登録・処理」。
