# システム概要資料

## 1. 概要

社内文書検索AI（RAG）は、社員が自然文で質問すると、登録済みの社内PDFから関連箇所を検索し、
生成AI（Claude）が**根拠に基づいた回答**を返す社内向けシステムです。
回答には必ず**根拠となるファイル名とページ番号（出典）**が表示され、文書にない情報は推測しません。

- 本番URL: https://rag-prpject.vercel.app
- 対象: 社内メールドメインを持つ社員（一般社員／管理者の2区分）

## 2. 解決する課題

- 文書の保管場所が分からず検索に時間がかかる。
- 新入社員が「どこに何があるか」を先輩へ都度質問する負担。
- 従来のキーワード検索では、言い回しの違いに弱い。

本システムは自然文の質問に対し、**意味的に近い箇所**をベクトル検索し、出典付きで回答することで上記を軽減します。

## 3. 主な機能

| 区分 | 機能 |
|---|---|
| 一般社員 | ログイン（社内メール）、自然文での質問、回答と出典の確認 |
| 管理者 | 上記に加え、PDF登録、文書一覧・処理状況の確認、再処理、削除 |
| 共通 | 回答不能の明示（該当情報がない場合）、出典（ファイル名/ページ）表示 |

## 4. 技術構成

| 領域 | 採用技術 |
|---|---|
| フロント/API | Next.js 16（App Router）/ TypeScript / Tailwind CSS |
| 認証 | Supabase Auth（マジックリンク・社内ドメイン限定） |
| データベース | Supabase PostgreSQL + pgvector（東京リージョン） |
| ストレージ | Supabase Storage（非公開バケット） |
| 文書のベクトル化 | OpenAI `text-embedding-3-small`（1536次元・cosine） |
| 回答生成 | Anthropic Claude `claude-sonnet-5` |
| PDF解析 | unpdf（ページ単位抽出） |
| ホスティング | Vercel（GitHub連携で自動デプロイ） |

## 5. 処理の流れ（要約）

1. **取り込み**: 管理者がPDFをアップロード→検証→保存→ページ単位で抽出→チャンク分割→ベクトル化→DB保存。
2. **質問**: 社員の質問をベクトル化→類似チャンクを検索（類似度しきい値・文書偏り抑制）→検索結果のみをClaudeへ→回答とchunkIdを受領。
3. **出典**: chunkIdをサーバーで検証し、ファイル名・ページを**DBから復元**して表示。根拠不足は「回答不能」。

詳細な図は「01-アーキテクチャ図」を参照。

## 6. 主な設定値（既定）

| 項目 | 値 | 変更方法 |
|---|---|---|
| チャンクサイズ / オーバーラップ | 約700 / 120 トークン相当 | 環境変数 `RAG_CHUNK_SIZE_TOKENS` / `RAG_CHUNK_OVERLAP_TOKENS` |
| 検索取得件数（topK） | 10 | `RAG_RETRIEVAL_TOP_K` |
| 類似度しきい値 | 0.15 | `RAG_SIMILARITY_THRESHOLD` |
| 1文書あたり最大採用件数 | 4 | `RAG_MAX_CHUNKS_PER_DOCUMENT` |
| Embeddingモデル / 次元 | text-embedding-3-small / 1536 | `EMBEDDING_MODEL` / `EMBEDDING_DIMENSIONS` |
| 回答モデル | claude-sonnet-5 | `ANSWER_MODEL` |
| アップロード上限 | 20MB | `RAG_MAX_UPLOAD_BYTES` |

> しきい値・件数は精度評価（下記）でチューニング済みの値です。

## 7. 精度（受け入れ基準と実績）

実文書に基づく評価（60問）での実績:

| 指標 | 実績 | 合格基準 |
|---|---|---|
| 回答内容の正答率 | 100% | 80%以上 |
| 出典表示率 | 100% | 100% |
| 回答不能質問への誤回答率 | 0% | 10%以下 |

評価は `npm run eval` により再現可能（LLM-as-judge で採点）。

## 8. セキュリティ

- APIキー・Service Role Key はサーバー専用（クライアントへ露出しない）。`.env.local` は Git 管理外。
- RLS（行レベルセキュリティ）有効、Storage は非公開、認可は middleware と API 層の**多層**で確認。
- 出典は AI の生成値を信用せず DB から復元。検索結果はデータとして扱い、PDF本文の指示に従わない。
- SQL はパラメータ化された検索関数（RPC）経由。ユーザー入力を文字列連結しない。

## 9. 品質保証

- 自動テスト 57件（ユニット/結合）。`lint` / `typecheck` / `build` を整備。
- 依存の既知脆弱性 0（`npm audit`）。

## 10. 現時点の制約（MVP範囲）

- 1問1答（会話履歴のサーバー保存なし）。
- スキャン（画像）PDFは非対応（テキストが取れない場合は「失敗」表示）。
- 回答は非ストリーミング（生成完了後にまとめて表示）。
- 対応形式はPDFのみ。Word/Confluence、部署別アクセス制御は対象外（Phase2提案参照）。
- PDF処理・チャットの実行時間上限はホスティングプランに依存（Vercel Pro推奨）。
