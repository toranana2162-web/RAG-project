# Phase 2 提案書（追加機能・概算工数・期待効果）

## 0. 前提

Phase 1（MVP）は完成・本番稼働済み（出典付きRAG・認証・PDF取り込み・精度評価合格）。
本提案は、MVPで対象外とした機能や運用上の改善を、優先度・概算工数・期待効果とともに整理したものです。

- 工数は**目安（人日）**。要件確定・既存環境により増減します。
- 「難易度」は実装/検証の複雑さ、「効果」は業務インパクトの目安。
- 前提コスト: OpenAI/Anthropic の従量課金、必要に応じ Vercel Pro（長時間処理・帯域）。

## 2. 施策詳細

### P1. 非同期取り込み基盤（優先度: 高 / 8〜12人日）
- **現状**: `/process` が同期処理（1文書ずつ、`maxDuration=300`）。大容量・大量PDFでタイムアウトの懸念。
- **提案**: ジョブキュー（例: Inngest / QStash 等）またはワーカーで非同期化。進捗表示、失敗時の自動リトライ、一括投入。
- **効果**: 初回200本規模の一括取り込みを安定化。運用負荷とタイムアウト事故を削減。
- **難易度**: 中〜高（外部基盤の選定・冪等設計）。

### P2. 会話履歴・マルチターン（優先度: 高 / 6〜10人日）
- **現状**: 1問1答（ステートレス）。
- **提案**: セッション単位の会話保存、直前文脈を考慮した検索・回答（クエリ書き換え含む）。
- **効果**: 「その制度の申請先は？」等の追い質問が可能に。利用継続率・満足度の向上。
- **難易度**: 中（文脈利用時の出典整合・コスト管理に留意）。

### P3. 原本PDFビューア（優先度: 中 / 4〜7人日）
- **現状**: 出典はファイル名・ページ番号のテキスト表示。Storageは非公開。
- **提案**: 署名付きURLで原本を表示し、出典クリックで該当ページへジャンプ。
- **効果**: 根拠の即時確認。回答への信頼性向上。
- **難易度**: 中（署名付きURL・権限・PDF表示）。

### P4. Word / その他形式対応（優先度: 中 / 4〜6人日）
- **現状**: PDFのみ。
- **提案**: `.docx` 等の抽出を追加（既存の抽出→チャンク→Embedding経路に接続）。
- **効果**: 取り込める文書の範囲拡大。
- **難易度**: 低〜中（形式ごとの抽出品質）。

### P5. スキャンPDFのOCR対応（優先度: 中 / 5〜8人日）
- **現状**: テキストのないPDFは「失敗」。
- **提案**: OCR（クラウドOCR等）を前処理に追加し、画像PDFをテキスト化。
- **効果**: 紙資料由来の文書も検索対象に。
- **難易度**: 中（OCR精度・コスト・処理時間）。

### P6. 回答ストリーミング表示（優先度: 中 / 3〜5人日）
- **現状**: 生成完了後に一括表示。
- **提案**: トークンの逐次表示。出典は生成後に検証・付与する現行方針を維持。
- **効果**: 体感速度・UXの改善。
- **難易度**: 低〜中（出典検証との順序整合）。

### P7. 監査ログ・利用分析（優先度: 中 / 5〜8人日）
- **現状**: 質問ログの保存なし。
- **提案**: 質問・回答・出典・利用者・日時を保存（機微情報の取扱いは要ポリシー確定）。よく聞かれる質問、回答不能率、文書別ヒット等を可視化。
- **効果**: 統制、FAQ整備、文書拡充の意思決定に活用。
- **難易度**: 中（個人情報・保持期間の方針、ダッシュボード）。

### P8. 部署別アクセス制御（優先度: 中 / 6〜10人日）
- **現状**: 認証済み社員は全文書を検索可。
- **提案**: 文書にアクセス区分を付与し、RLSと検索（match_chunks）に権限フィルタを組み込み。
- **効果**: 機密度に応じた閲覧分離。人事・経理等の限定文書に対応。
- **難易度**: 中〜高（データモデル拡張・RLS/検索双方の権限整合）。

### P9. 回答フィードバックと改善ループ（優先度: 低 / 3〜5人日）
- **提案**: 回答への👍/👎と自由記述、収集結果を評価データ（`scripts/eval`）に還元。
- **効果**: 実利用に基づく継続的な精度改善。
- **難易度**: 低。

### P10. Confluence / Slack 連携（優先度: 低 / 8〜14人日）
- **提案**: Confluenceページの定期取り込み、Slackからの質問・回答（Bot）。
- **効果**: 文書源の自動同期、社員の到達性向上。
- **難易度**: 高（各API連携・権限・差分更新）。

### P11. 検索精度の高度化（優先度: 中 / 5〜9人日）
- **提案**: ベクトル検索＋キーワード（全文）検索のハイブリッド化、上位候補のリランク（例: 追加のスコアリング）。
- **効果**: 言い回し依存の取りこぼし低減、正答率・網羅性の底上げ。
- **難易度**: 中。

## 4. 期待効果（総括）

- **利用の定着**: 会話履歴・原本ビューア・ストリーミングで日常利用に耐えるUXへ。
- **カバレッジ拡大**: Word/OCR/連携で「検索できる文書」を大幅拡大。
- **統制と改善**: 監査ログ・フィードバックで、精度と運用を継続的に改善。
- **セキュリティ強化**: 部署別ACLで機密文書にも展開可能。

## 5. 留意点・前提

- 追加機能により OpenAI/Anthropic の**API利用コストが増加**します（会話履歴・OCR・大量取り込み等）。事前に想定利用量での試算を推奨。
- 長時間処理・帯域の安定運用には **Vercel Pro** 等の上位プランを推奨。
- 監査ログ・部署別ACLは、**個人情報/機密の取扱いポリシー**の確定が前提となります。
- 各工数は概算です。要件定義後に見積を確定します。
